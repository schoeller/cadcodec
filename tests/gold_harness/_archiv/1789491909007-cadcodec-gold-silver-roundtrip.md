# Plan: Gold-vs-Silver DWG Roundtrip Harness + Autonomous Fix Loop for cadcodec

## Goal
Build a roundtrip test mechanism that uses **LibreDWG as the golden reference** to find missing/wrong **non-header** file-structure definitions in **cadcodec** (crate `acadrust`, the "silver" spec), then drive an **autonomous iterative fix loop** in which the executing agent edits cadcodec's silver spec until its non-header output matches gold across the test-data corpus.

"Roundtrip" verifies **both** cadcodec's reader **and** writer: cadcodec reads a gold DWG, re-encodes it, and the result is re-decoded — with LibreDWG acting as the independent oracle on both the original and the rewritten file.

The **header is tested laxly** (out of the strict-diff scope — only entity/object non-header parts must match exactly). The loop is **bounded to the test-data corpus** and must **respect the R2000–R2018 version scope**.

## Confirmed decisions (from user)
| Decision | Choice |
|---|---|
| Comparison oracle | **JSON field-level diff** (libredwg `dwgread -O JSON` vs acadrust serde JSON) |
| Roundtrip meaning | Verify **both cadcodec reader and writer**; libredwg validates both ends |
| Environment | **WSL** — build libredwg from source; run cadcodec via `cargo` |
| Version scope | **R2000–R2018** (AC1015, AC1018, AC1021, AC1024, AC1027, AC1032) |
| Silver JSON source | **Reuse cadcodec's `serde` feature** + a dump bin that **re-includes serde-skipped `EntityCommon` fields** |
| Fix-loop coverage | **Bounded to the test-data corpus**; gap entities logged as out-of-loop |
| Loop convergence target | **Zero non-header field diffs** across the covered corpus |
| Version-scope guard | **Gate each fix by the gold spec's version predicate; verify all 6 versions** |
| Safety / regression gate | **Per-fix checkpoint: `git commit` if git is available, else record in `report.md`; corpus non-regression + `cargo test` green** |
| Convergence reachability | **Curated `ignore_fields.toml` of gold-only derived/verbatim fields, frozen during the loop** |

  - Dispatch by fixed type codes 0–82 + class-remapped types (500+) in `dwg_document_builder.rs` (`resolve_type_code`, `build_class_type_map`).
  - `EntityType` enum: 48 variants in `src/entities/mod.rs`.
  - Existing in-memory roundtrip `tests/roundtrip.rs` (`DwgWriter::write_to_vec` -> `DwgReader::from_stream`), across all 6 write versions, **but it never reads an external gold `.dwg`** — so silver-vs-gold divergence is currently untested.
  - `serde` is an optional feature (`serde = ["dep:serde", ...]`); `Cargo.toml` already has `serde` + `serde_json` (dev-dep).
- **libredwg** (C, GPL-3):

Entities `DWG_ENTITY(name)…DWG_ENTITY_END`, objects `DWG_OBJECT(name)…DWG_OBJECT_END`, fields via `FIELD_*` macros with `PRE/VERSIONS/SINCE/UNTIL/LATER_VERSIONS` and `DXF/JSON/DECODER/ENCODER` guards.

AcDs solid data in `src/acds.spec`. Class map in `src/classes.inc` / `classes.c`.
  - Header-side specs (explicitly **excluded** from the "match" scope): `header.spec`, `header_variables*.spec`, `auxheader.spec`, `2ndheader.spec`, `r2004_file_header.spec`, `summaryinfo.spec`, `template.spec`, `security.spec`, `revhistory.spec`, `filedeplist.spec`, `objfreespace.spec`, `vbaproject.spec`, `appinfo.spec`.
  - JSON exporter `src/out_json.c`: emits objects/entities keyed by spec field names (`_path_field`), 2/3D points as `[x,y(,z)]`, handles as `[code,size,value(,absref)]`, colors as nested CMC hashes, `_subclass` markers, floats `%.14f`. This is the **gold field vocabulary**.
  - Programs: `dwgread` (supports `-O JSON`), `dwgwrite`, `dwgrewrite`, `dwg2dxf`, `dxf2dwg`. Writer officially reliable only ≤R2004 — **irrelevant** because libredwg is used only to *decode* (oracle), never to write.
  - Test data `test/test-data/{r13,r14,2000,2004,2007,2010,2013,2018}/` + `example_*.dwg`, `sample_*.dwg`. In-scope versions: `2000` (23 .dwg), `2004` (21), `2007` (18), `2010` (18), `2013` (19), `2018` (19) + top-level `example_*/sample_*`.

## Scope boundary (what "non-header" means for the diff)
Gold `dwgread -O JSON` emits a single top-level object whose keys are (in order): `created_by`, `FILEHEADER`, `HEADER`, `CLASSES` (R13+), `OBJECTS` (array), `THUMBNAILIMAGE` (opt), and optional section records `ObjFreeSpace`, `SecondHeader`, `Template`, `AuxHeader`, `R2004_Header`/`R2007_Header`, `SummaryInfo`, `VBAProject`, `AppInfo`, `AppInfoHistory`, `FileDepList`, `Security`, `RevHistory`, `AcDs`.

- **IN scope (must match gold):** the top-level **`OBJECTS` array only**. It contains both entities and non-entity objects as one array; each element is a hash discriminated by an `entity` vs `object` key holding the type name (`"LINE"`, `"LAYER"`, …). Compare per-object fields defined by `dwg.spec`, `dwg2.spec`, `common_entity_data.spec`, `common_entity_handle_data.spec`, `common_object_handle_data.spec`, and `acds.spec`. There is no `num_objects`/CRC key — count array elements, don't read a count field.
- **OUT of scope (header; lax — drop before diffing):** every other top-level key listed above (`created_by`, `FILEHEADER`, `HEADER`, `CLASSES`, `THUMBNAILIMAGE`, `ObjFreeSpace`, `SecondHeader`, `Template`, `AuxHeader`, `R2004_Header`, `R2007_Header`, `SummaryInfo`, `VBAProject`, `AppInfo`, `AppInfoHistory`, `FileDepList`, `Security`, `RevHistory`, `AcDs`). The normalizer drops these by exact name.

## Architecture
```
            LibreDWG (gold, WSL)                     cadcodec/acadrust (silver)
            -------------------                     ---------------------------
orig.dwg --> dwgread -O JSON --> gold_orig.json  --> [normalize] --+
orig.dwg ---------------------------------------> DwgReader.read() |
                                                     |             |
                                                     v             |
                                              CadDocument --serde--> silver_orig.json
                                                     |             |
                                              DwgWriter            |
                                                     v             |
                                              rt.dwg ---------> dwgread -O JSON --> gold_rt.json
                                                     |             |
                                              DwgReader.read()     |
                                                     v             v
                                              silver_rt.json   [normalize + DIFF] --> report
```

Three diffs per file:
1. **Read fidelity:** `gold_orig.json` vs `silver_orig.json` → finds fields cadcodec's *reader* drops/misparses.
2. **Write fidelity:** `gold_orig.json` vs `gold_rt.json` (libredwg reads cadcodec's rewritten DWG) → finds fields cadcodec's *writer* omits/corrupts, validated by the gold reader.
3. **Internal consistency:** `silver_orig.json` vs `silver_rt.json` → cadcodec read→write→read self-check (complements existing `tests/roundtrip.rs` with real gold files).

## Work breakdown (ordered)

### Phase 0 — Fetch sources & test data (WSL)
- Clone into the WSL filesystem (not `/mnt/c`, for build speed): `~/work/libredwg` and `~/work/cadcodec` (user's fork `schoeller/cadcodec`).
- The `test/test-data` DWGs come with the libredwg clone. Confirm presence of `example_2000.dwg`, `2000/Line.dwg`, etc.

### Phase 1 — Build the gold oracle (WSL)
- Install deps: `build-essential autoconf automake libtool texinfo perl python3 jq` (and `libxml2` utils optional). Disable bindings for speed: `./configure --disable-bindings --disable-docs`.
- `sh ./autogen.sh && ./configure --disable-bindings --disable-docs && make -j` → produces `programs/dwgread`.
- Smoke test: `programs/dwgread -O JSON test/test-data/2000/Line.dwg | jq .` returns entity JSON.
- Record the built `dwgread` absolute path as the harness's `GOLD_DWGREAD` env var.

### Phase 2 — Silver JSON dump (cadcodec)
- Add `examples/dwg2json.rs` (or `src/bin/dwg2json.rs`) to cadcodec that:
  - `DwgReader::from_file(path)?.read()?` → `CadDocument`.
  - Serializes with `serde_json::to_string_pretty(&doc)` (requires `--features serde`).
  - **Re-includes serde-skipped fields (decision):** plain serde omits the 12 `EntityCommon` round-trip fields (`material_flags`, `material_handle`, `shadow_flags`, `plotstyle_flags`, `plotstyle_handle`, `linetype_handle`, `entity_mode`, the three visual-style handles, `graphic_data`, `has_ds_data`) — exactly the non-header common fields under test. The bin must NOT serialize `CadDocument` directly; it builds a dump wrapper that, per entity, merges the serialized struct with these skipped fields read from the live `EntityCommon`, so the silver JSON covers the same field set gold emits. (Raw byte blobs like `graphic_data`/`raw_acds_data` stay excluded — they are verbatim storage, not comparable structure.)
  - Prints to stdout or `--out`.
- Build: `cargo build --release --features serde --example dwg2json`.
- Verify it runs on a gold DWG and emits parseable JSON that includes `material_flags`/`plotstyle_flags` on an entity.
- Note: acadrust field names differ from libredwg's (e.g. `Line.start` vs gold `start`, acadrust `Line.normal` vs gold `extrusion`); the normalizer maps them.

### Phase 3 — Normalizer + differ (harness core)
New tooling, language: **Python 3** (in WSL) for fast iteration on JSON mapping. Lives in a new `cadcodec/tests/gold_harness/` dir (scripts only; not a cargo test yet).
- `normalize_gold.py`: parse libredwg JSON → canonical object list. Keep ONLY the top-level `OBJECTS` array; drop all header/section keys listed in "Scope boundary". For each element read the `entity`/`object` discriminator as the type. Emit `{type, handle, fields:{...}}` with points collapsed to `[x,y,z]`, colors to `{index,rgb}`, and handles kept raw for pass 1.
- `ignore_fields.toml` (decision — frozen during loop): a curated, version-controlled list of gold-only derived/verbatim fields the differ skips (start: `bitsize`, `size`, `preview`, `preview_size`, `preview_exists`, `preview_is_proxy`, `_subclass`, `entmode` numeric, `num_*`, `eed`, `reactors` ordering, `opts_r11`, `flag_r11`, `extra_r11`). This file is written ONCE when the harness is built and is **not editable during the fix loop** — extending it mid-loop is exactly the "weakening the differ" the invariant forbids. "Zero diffs" means zero diffs on the non-ignored field set.
- `normalize_silver.py`: parse acadrust serde JSON → same canonical shape. Map `EntityType` variant names → gold type names, and per-variant field names → gold field names (a per-entity mapping table; start with the ~15 most common entities). Reshape: expand silver polylines into child vertex records to match gold's `VERTEX_*` expansion; read silver's `block_records` to resolve block membership.
- `diff_fields.py`: two passes. **Pass 1** builds a `handle_value → type` map from each side independently (gold: the element's `handle`; silver: `common.handle`). **Pass 2** aligns entities across the two files by `(type, index-in-type)` (handles are reassigned on rewrite, so never align by raw handle), then diffs field sets; a handle-valued field matches if both sides resolve to the same target **type** (via the pass-1 maps), not the same raw id. Report `missing_in_silver`, `wrong_value`, `extra_in_silver`, skipping fields in `ignore_fields.toml`. Tolerances: floats `~1e-6` rel; strings exact after UTF-8 normalization.
- Output a per-file, per-entity, per-field report (JSON + human summary) that names the exact gold field cadcodec lacks.

### Phase 4 — Roundtrip driver
- `run_roundtrip.py <file.dwg>`:
  1. `gold_orig = dwgread -O JSON file.dwg`
  2. `silver_orig = acadrust dwg2json file.dwg`
  3. `rt.dwg = acadrust rewrite(file.dwg)` (add a `--rewrite` mode to the dump bin, or a second tiny bin `dwgrewrite.rs` that read→writes). **The rewrite must target the SAME DWG version as the source file** (the version the `DwgReader` read into the document); do not re-target versions — the write-fidelity diff (`gold_orig` vs `gold_rt`) is only meaningful within one version, because many fields are version-gated and would spuriously differ across versions.
  4. `gold_rt = dwgread -O JSON rt.dwg`; `silver_rt = acadrust dwg2json rt.dwg`.
  5. Run the three diffs; aggregate.
- Batch mode over `test/test-data/{2000,2004,2007,2010,2013,2018}/*.dwg` + top-level `example_*.dwg`/`sample_*.dwg` in scope. Parallelize with `xargs -P` or GNU parallel.
- Exit non-zero and write `report.json` + `report.md` summarizing which entity types/fields diverge, ranked by frequency.

### Phase 5 — Integrate as a cargo test (gated)
- Add `cadcodec/tests/gold_roundtrip.rs`, gated behind `#[cfg(feature = "gold-harness")]` (new off-by-default feature) and env vars `GOLD_DWGREAD` + `GOLD_TESTDATA`. When unset, the test skips (so normal `cargo test` stays hermetic and fixture-free, preserving cadcodec's existing convention).
- The test shells out to the Phase 4 driver for a small representative subset (e.g. `2000/Line.dwg`, `2000/circle.dwg`, `2018/Text.dwg`) and asserts zero `missing_in_silver` fields for those.

### Phase 6 — Autonomous iterative fix loop (make silver match gold)
The executing agent runs this loop after Phases 0–5 are in place. It edits cadcodec source until the covered corpus reaches **zero non-header, non-ignored field diffs**, or every remaining offender is provably blocked.

**Precondition:** this loop must run under an **implementation-capable agent** (file edits + `cargo` + subprocess), NOT in plan mode. Git mutations are optional (see step 6). The current plan-authoring session only produces Phases 0–5 artefacts and the plan itself.

**Corpus the loop operates on (bounded — decision):** the in-scope version dirs `{2000,2004,2007,2010,2013,2018}/*.dwg` plus top-level `example_{2000,2004,2007,2010,2013,2018}.dwg` and `sample_{2000,2018}.dwg`. Entity types with no gold file (see "Corpus coverage → gaps") are written to `report.md` under `OUT OF LOOP (no gold coverage)` and are NOT worked on.

**Convergence target (decision):** for every covered file, `normalize(gold_orig)` ≡ `normalize(silver_orig)` on the non-header, **non-ignored** field set (see `ignore_fields.toml`, Phase 3), AND `normalize(gold_orig)` ≡ `normalize(gold_rt)` (gold re-reads cadcodec's rewrite) on the same set. Header keys are excluded from the strict diff (lax header).

**Loop body (repeat until converged or all blocked):**
1. **Baseline.** Run the Phase 4 driver over the whole covered corpus. Produce `report.json`/`report.md` ranking `(entity_type, gold_field, dwg_version)` divergences by frequency and by a fixed priority: read-fidelity first (Phase-4 diff #1), then write-fidelity (#2), then internal consistency (#3). Geometry-correctness fields (points, radii, angles, counts) rank above cosmetic/default fields.
2. **Pick top offender.** Choose the highest-ranked `(entity_type, gold_field)` not already marked blocked.
3. **Consult gold.** Open `dwg.spec`/`dwg2.spec` at that `DWG_ENTITY(...)`/`DWG_OBJECT(...)` block (and `common_entity_data.spec` / `common_entity_handle_data.spec` for common fields). Record the exact `FIELD_*` macro, bitcode type, and the `PRE/VERSIONS/SINCE/UNTIL/LATER_VERSIONS` gating.
4. **Fix silver, version-gated (decision).** Edit the matching cadcodec `read_<entity>` in `object_reader/entities.rs` and its mirror in `object_writer/entities.rs`. Add/correct the field using the same bitcode primitives (`read_bit_double_with_default`, `read_bit_extrusion`, `read_bit_thickness`, `read_bit`, …) and gate it behind the SAME version predicate gold uses (`r2000_plus()`, `r2004_plus()`, `r2007_plus()`, …). **Do NOT modify version dispatch, decompression, CRC, or the section map** — only the per-field read/write bodies. If gold gates a field `SINCE R_2007a`, silver must read/write it only under `r2007_plus()`, never earlier.
5. **Verify across all 6 versions (decision).** Re-run the driver over the FULL covered corpus (all version dirs), not just the failing file, to catch cross-version regressions. Confirm the target field now matches and the corpus-wide non-header diff count strictly decreased.
6. **Regression gate + checkpoint (decision).** Require: (a) `cargo test` green (existing suite, harness feature off), (b) `cargo test --features serde` green, (c) corpus non-header diff count strictly decreased (no new divergences introduced). If all pass, **checkpoint the fix: `git commit` if git mutations are available in the agent's environment; otherwise apply the change to the working tree and record it in `report.md`** (message names the entity/field and the gold spec reference). If any check fails, revert the change (`git revert`/`git checkout` if git is available, else restore the prior file contents saved before editing) and mark the offender blocked with the reason.
7. **Blocked handling.** If an offender cannot converge after **5 fix attempts** (or requires touching out-of-bounds code: version dispatch, decompressor, CRC), mark it `BLOCKED: <reason>` in `report.md` and move to the next. Blocked items are revisited only after all non-blocked offenders are exhausted.
8. **Stop conditions.** Stop when (a) corpus-wide non-header, non-ignored diff count == 0 (SUCCESS), or (b) every remaining offender is BLOCKED (PARTIAL — report). Emit final `report.md` listing: fixed fields (with commit hashes where git was available, else working-tree records), blocked fields (with reasons), and out-of-loop entity types (no gold coverage).

**Loop invariants the agent must preserve:**
- Never edit gold (libredwg) — it is read-only oracle input.
- Never weaken the differ/normalizer to make a diff pass — no adding tolerances, no dropping fields, and **no editing `ignore_fields.toml`** during the loop.
- Never change the header strictness — header stays lax throughout.
- Each checkpoint must leave the build green; the working tree must never be left broken.

**Version-scope guard (explicit):** a fix is only valid if it is gated to the exact DWG versions gold specifies. The agent must confirm, for each touched field, that the field is read/written under the identical version predicate in both the reader and the writer, and that no other version's behavior changed (verified by step 5).

## Risks / mitigations
- **serde(skip) on common fields (resolved by design):** `EntityCommon` skips the non-header round-trip fields, so a naive serde dump would false-positive them as missing. Mitigated per decision: the dump bin re-includes them from the live struct (see Phase 2). Raw byte blobs stay excluded intentionally.
- **Field-name mismatch** between serde JSON and gold: mitigated by the per-entity mapping table; start small (top entities), grow iteratively.
- **Structure mismatch (not just names):** gold nests objects under `OBJECTS`/`ENTITIES` and expands polylines into child `VERTEX_*` records; acadrust nests vertices inside the parent polyline and stores blocks via `block_records`. The normalizer must reshape (expand/fold) before field diffing, not just rename keys.
- **Handle/ordering instability** across a rewrite (handles are reassigned): align entities by `(type, ordinal)`, never by raw handle value; compare handles only by resolved target *type*.
- **Unknown/proxy entities**: cadcodec `Unknown`/`Extended` and libredwg skipped objects will not align; the differ must tolerate count mismatches and report them as coverage gaps, not hard errors.
- **libredwg read warnings** on advanced R2010+ objects: treat gold `dwgread` non-zero exit / `Error` log lines as "gold cannot decode → skip file", not a silver failure.
- **Float formatting**: gold uses `%.14f`; normalize with rel-tolerance, and NaN→0 (gold release build already coerces NaN).
- **Build time** for libredwg in WSL: use `--disable-bindings --disable-docs`; cache the build dir.
- **Strings/codepages**: pre-2007 files use legacy codepages; normalize both sides to UTF-8 before compare (gold already emits UTF-8).
- **Corpus gaps limit the loop:** the loop cannot fix MTEXT/DIMENSION/TABLE/INSERT/etc. (no gold file). Mitigation: they are explicitly logged out-of-loop; do not let the agent synthesize or guess their structure.
- **Autonomous-loop drift:** an agent might "fix" a diff by weakening the normalizer, widening tolerances, or extending `ignore_fields.toml` mid-loop. Mitigation: loop invariants forbid editing the differ/normalizer/gold/`ignore_fields.toml` during the loop; these are fixed oracles.
- **Git unavailable in some environments:** plan mode and this authoring session block git mutations. Mitigation: step 6 checkpoints via commit only when git is available, else records in `report.md`; the regression gate itself is VCS-independent.
- **Cross-version regression:** a fix for one version can break another. Mitigation: step 5 re-runs the full corpus every iteration; step 6 gates on corpus-wide diff count strictly decreasing.
- **Non-convergence / oscillation:** a field may flip between two wrong states. Mitigation: 5-attempt cap per offender, then mark BLOCKED and move on; revisit only after others are exhausted.
- **Writer-only divergences:** some diffs only appear in `gold_rt` (cadcodec's rewrite). These are valid targets (writer must match gold too), but require fixing `object_writer/`, not the reader.

## Validation
- `programs/dwgread -O JSON` runs clean on a sample of in-scope gold DWGs.
- `cargo build --release --features serde` succeeds; `dwg2json` emits valid JSON on a gold DWG including re-included `EntityCommon` fields (`material_flags`, `plotstyle_flags`).
- Harness produces a `report.md` ranking divergent `(entity, field)` pairs across the in-scope corpus.
- At least one real divergence is found, fixed in cadcodec, and confirmed via re-run (the mechanism demonstrably closes a gold-vs-silver gap).
- `cargo test` (default, harness feature off) remains green and fixture-free.
- **Fix loop:** after running, the covered corpus reaches zero non-header, non-ignored field diffs (SUCCESS) or every remaining offender is BLOCKED with a recorded reason (PARTIAL); `report.md` lists fixed fields, blocked fields, and out-of-loop entity types. `cargo test` and `cargo test --features serde` are green at every checkpoint.

## Future work (explicitly out of current scope)

### F1 — Header silver-vs-gold comparison
The header is lax/out-of-scope for the current loop. A later phase can extend the same differ to header variables, reusing all existing machinery:

- **Gold source:** `dwgread -O JSON` top-level `FILEHEADER` (contains `version` string e.g. `"AC1021"`, `maint_rel_version`, `codepage` int, section addresses, R2004+ unknowns) and `HEADER` (every header variable by its spec `$VAR` name — `LUNITS`, `LUPREC`, `EXTMIN`/`EXTMAX`, `LIMMIN`/`LIMMAX`, `HANDSEED`, `CLAYER`, `TEXTSTYLE`, `DIMSTYLE`, the full `DIM*` set, `TDUCREATE`/`TDUUPDATE` as `[days, ms]`, `CECOLOR` as a CMC hash, control-object/dictionary handles, R2007+ keys like `CAMERADISPLAY`, `LATITUDE`, …). Keys are version-gated (`SINCE`/`UNTIL`); gold omits `num_*` counters and NaN doubles.
- **Silver source:** `CadDocument.header: HeaderVariables` (serde-derivable; snake_case fields with the `$VAR` name in each doc comment — e.g. `model_space_extents_min` → `EXTMIN`, `linear_unit_format` → `LUNITS`, `code_page` → `DWGCODEPAGE`). `CadDocument.version`/`maintenance_version` map to `FILEHEADER.version`; `header.code_page` (string like `"ANSI_1252"`) maps to `FILEHEADER.codepage` (int).
- **Work items:** (a) add a header-var name mapping table (snake_case ↔ `$VAR`, derivable mechanically from `HeaderVariables` doc comments); (b) extend `normalize_*` for header types — points (`Vector3` object ↔ `[x,y,z]` array), handles (`Handle` ↔ `[code,size,value,absref]`), colors (`Color` enum ↔ CMC hash), dates (julian `f64` ↔ `[days, ms]`); (c) treat version-gated gold keys absent for a file's version as "not present", never as mismatch.
- **Recommended strictness tier:** do NOT require full ~250-var equality. Compare a curated subset of semantically load-bearing vars first (`LUNITS`, `INSUNITS`, `MEASUREMENT`, `EXTMIN`/`EXTMAX`, `DWGCODEPAGE`, `HANDSEED` ordering sanity), then widen. Header handles (`BLOCK_CONTROL_OBJECT`, dictionary handles) compare by resolved target type, same rule as entities.
- **Caution:** `HANDSEED`/section addresses in `FILEHEADER` legitimately change on rewrite — exclude them from the write-fidelity header diff, include them only in read-fidelity.

### F2 — Manually generating coverage-gap files with AutoCAD/BricsCAD
The corpus gaps (MTEXT, DIMENSION, TABLE, REGION, static INSERT/BLOCK, MLEADER, VIEWPORT, IMAGE, MESH, 3DFACE, SOLID, ATTDEF/ATTRIB, TOLERANCE, WIPEOUT) can be closed by authoring fixtures in a real CAD application, after which the existing loop covers them with **no harness changes** (the corpus is the only input):

1. **Author minimal files:** in AutoCAD or BricsCAD, create one drawing per gap entity — e.g. `MText.dwg`, `Dimension.dwg` (one file per dimension kind: rotated/aligned/angular/radial/diameter/ordinate/arc), `Table.dwg`, `Region.dwg`, `Insert.dwg` (static block reference with attributes → also covers ATTRIB/ATTDEF/SEQEND), `MLeader.dwg`, `Viewport.dwg` (paperspace), `Image.dwg`, `Mesh.dwg`/`PolyfaceMesh.dwg`, `3DFace.dwg`, `Solid.dwg` (2D), `Tolerance.dwg`, `Wipeout.dwg`. Keep each file minimal (one or two entities on layer 0) so diffs stay localizable — the existing per-entity naming convention (`Line.dwg`, `Arc.dwg`, …) is the model.
2. **Save per version:** use SAVEAS to write each file in each in-scope format — R2000 (AC1015), R2004 (AC1018), R2007 (AC1021), R2010 (AC1024), R2013 (AC1027), R2018 (AC1032) — and place it in the matching `test/test-data/<version>/` dir. (AutoCAD and BricsCAD both support saving to these older DWG formats; some entity types are version-limited, e.g. MLEADER/TABLE require R2000+/R2004+ — only produce versions where the entity natively exists.)
3. **Qualify each file as gold before use:** run `programs/dwgread -O JSON` on it; only files libredwg decodes without `Error` enter the corpus (a file gold can't read cannot drive the loop). Record authoring tool + version in a `.txt` companion per the existing convention (`Line.dwg` → `Line.txt`).
4. **Provenance/licensing:** fixtures authored from scratch in the CAD app are clean test data (no third-party content). Note the generator in the companion `.txt`; do not copy sample drawings from other products.
5. **Loop integration:** drop the new files into the corpus dirs, re-run the Phase 4 driver, and the entity types move from "OUT OF LOOP" to covered automatically. Update the plan's "Corpus coverage → gaps" list as gaps close. The fix loop (Phase 6) then iterates on them under the same convergence and safety rules.
