## 1. Evidence: why each gate exists (verified this campaign)

1. **Symmetric-bug blindness.** Four R2013+ entity-stream genus bugs
   (leading acis_empty bit, phantom R2007 BL, phantom silhouettes count
   outside the isoline_present gate, unconditional 3DSOLID history_id
   handle) were each symmetric in reader+writer: captured round-trips
   stayed byte-faithful, the census stayed 0/0, and BricsCAD refused
   every constructed solid. Only the gold oracle's manual `-v5` trace
   caught them (commit `37a0675`).
2. **AcDs container blindness.** The AcDsPrototype_1b section is not
   censused at all. The silver writer builds an IntelliCAD-style
   `ds_version=1` container; native R2018 files carry `ds_version=16`
   with a different segment graph. Verdict matrix (BricsCAD,
   user-verified):
   - silver ds_version=1 container + CLASSIC ACIS SAB -> opens clean
     (gen_all `9ed5e42` round, 2026-09-24)
   - silver ds_version=1 container + ASM SAB (even byte-verbatim
     native ASM content) -> modeler restore fails ("Out of Memory" /
     "Object improperly read")
   - native ds_version=16 container + ASM SAB -> clean (authored files)
   The blob dialect and the container revision must PAIR. Nothing in
   the harness currently enforces or even reports this.
3. **Constructed-content blindness.** `gen_all_entities_all_versions.dwg`
   (the canonical constructed file, regenerated by
   `cargo run --example gen_all_entities_all_versions_dwg`) has NO
   gold-decode gate. Its md5 is tracked manually; its gold-oracle
   decode is never checked.

## 2. Verified data sources (do not re-derive; confirmed 2026-09-25)

### 2.1 Gold side (dwgread)

- `dwgread -O JSON <file>` emits a top-level `"AcDs"` object for R2013+
  files. Fields (libredwg `src/acds.spec`, FIELD_RL each):
  `file_signature, file_header_size, unknown_1, version, unknown_2,
  ds_version, segidx_offset, segidx_unknown, schidx_segidx,
  datidx_segidx, search_segidx, prvsav_segidx, file_size`,
  plus `segidx[]` entries `{index, offset, size}` (91 entries on the
  native Box_2018 fixture; `num_segidx` is the array length) and a
  `segments[]` array (per-segment: signature 0xD5AC, name, segment_idx,
  is_blob01, segsize, unknown_2, ds_version, unknown_3,
  data_algn_offset, objdata_algn_offset, padding "UUUUUUUU").
  NOTE: libredwg's AcDs decode is itself partial (its verbose trace
  warns "Not matching number of ... AcDs SAB data" on native files) —
  the jard/segidx fields above are the reliable surface.
- `dwgread -v5 -o /dev/null <file>` traces the AcDs header decode to
  stderr (grep `segidx_offset|num_segidx|ds_version|segments\[0\]`).
- Section map: JSON top-level `"R2004_Header"` carries `numsections,
  last_section_id, last_section_address, section_map_id, ...`;
  `"FILEHEADER"` carries version fields. Section names appear in the
  verbose trace as `section_info[i] <name> type <n>`.
- Gold ERROR lines: `dwgread -v5` prints `ERROR: ...` to stderr on
  decode failures (e.g. "Invalid revision_bytes size" caught the
  entity-stream bugs).

### 2.2 Silver side (acadrust)

- `tests/gold_harness/src/bin/dwg2json.rs` currently emits NO AcDs
  projection (verified: no acds/segidx keys in its JSON output).
- The reader already exposes the raw section:
  `DwgReader::get_section_buffer("AcDb:AcDsPrototype_1b", &info)`
  (`src/io/dwg/dwg_reader.rs:1152`, used for SAB extraction). The jard
  header is 14 little-endian u32s from byte 0; `segidx_offset` (field
  7) points at the segment-index table. A faithful silver projection
  belongs in the dump (`dwg2json.rs`) or a new harness bin — per
  AGENTS.md, as a projection, never data-hiding.
- `dump_section_bytes` bin already exists for raw byte ground truth:
  `cargo run --bin dump_section_bytes -- FILE ADDR SIZE
  "AcDb:AcDsPrototype_1b"`.

## 3. The four gates to implement

### G1 — AcDs header census (read + write fidelity)

Silver decodes the jard header + segments[0] + segidx summary
(nonzero-entry count and their offsets/sizes) from its section buffer;
gold provides the same from its JSON. Compare:
- read fidelity: gold_orig vs silver_orig (per file)
- write fidelity: gold_orig vs gold_rt (the silver rewrite re-emits the
  section from its own builder — this is where container divergence
  shows)
Expected initial state (do NOT hide these; they are the work queue):
`ds_version 1 vs 16`, segidx position (silver: last; native: first,
segidx_offset=128), `num_segidx 8 vs 91`, segment ordering. The report
should rank them exactly like the field census ranks (type, field)
pairs. Structural fields (ds_version, num_segidx, ordering) are
hard-comparable; size/offset fields (file_size, per-segment offsets)
are rewrite-variable — compare with a documented tolerance or list
them separately with the justification in the report.

### G2 — Section census

Per file: set of section names + decompressed sizes, silver view vs
gold view, and gold_orig vs gold_rt. Catches missing/mis-sized
sections (the AcDs builder returning empty on a failed queue would
show here). Sources: gold verbose trace section_info lines or JSON;
silver via its own section map (the reader's section enumeration).

### G3 — Constructed-content gate (the symmetric-bug killer)

Run `dwgread -v5` over `gen_all_entities_all_versions.dwg` and assert
ZERO lines matching `^ERROR` (stderr). Wire it into the zero-keeping
workflow (README "The zero-keeping workflow") as a required step after
the corpus run, and mirror it as a `cargo test --features gold-harness`
test alongside `gold_roundtrip.rs` (env-gated like that test: skip with
a notice when GOLD_DWGREAD is unset). This gate alone would have caught
all three failing rounds at commit time.

### G4 — SAB dialect marker census

For every ACIS entity (3DSOLID/REGION/BODY) and every AcDs `_data_`
record: extract the blob's magic string (`ACIS BinaryFile` vs
`ASM BinaryFile`) and the version u32 at byte 15. Report silver vs gold
on originals. The pairing invariant (classic blobs in a ds_version=1
container, ASM in a ds_version=16 one) becomes a ranked divergence the
moment a writer change breaks it. Silver side: the SAB bytes are
already in the entity JSON (`acis_data.sab_data`) — decode the 15-byte
magic + u32 in the projection.
